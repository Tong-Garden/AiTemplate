Create User Flow
Complete sequence for creating a new user account with validation
Administrator fills out the Create User form with name, email, phone, and active status. Form validates input, checks for duplicate emails, then submits to the backend API. Success returns the new user with auto-generated ID; failure returns validation errors.

List and Pagination Flow
Displaying users with pagination controls and data grid
Administrator loads the Users page showing a Syncfusion DataGrid with all users. API returns paginated results (default 20 per page). Grid displays pagination controls (Previous, Next, page indicator). Administrator can navigate between pages, change limit, or perform inline actions on each row.

Delete User Flow
Safe deletion of user accounts with implicit confirmation
Administrator clicks delete icon on a user row in the DataGrid. DELETE request is sent to backend with the user ID. Success removes the user from the database and updates the grid; failure displays error toast. User data is permanently removed (no soft delete in v1).

Bulk Upload Flow
Importing multiple users from an Excel file
Administrator clicks the Upload button, selects a .xlsx/.xls file, and submits. Frontend validates file type. Backend parses Excel, creates users with skipped duplicates. API returns count of successfully imported users. Toast confirms import with count and skipped duplicates are silently ignored.

Error Handling Flow
All error scenarios and how they surface to the user
The system handles multiple error types: validation errors (form field level), business logic errors (duplicate email, not found), and server errors. All are caught, parsed into structured error objects, and displayed appropriately: field errors in forms, general errors in toasts, and no stack traces exposed to the user.

System Architecture and Data Flow
Full-stack architecture: Frontend React UI, Zustand store, services, API client, backend FastAPI, domain logic, repositories, database schema
Complete system architecture showing all layers from React UI through backend domain logic. Data flows: UI dispatches actions to Zustand store → services validate and map → API client makes HTTP calls → FastAPI routers handle requests → services execute business logic → repositories persist data. Response data flows back through mappers to store to UI.
