Executive Overview
What this feature is, why it exists, and who it serves
The Company feature stores the organisations the system works for: each has a name, address, phone number and IANA timezone. It provides full create, read, update and delete through a paginated grid and a creation form.

Problem Statement

Other features need a consistent record of the company they act for, including the timezone used to interpret dates and times. Without a managed company record, that data is scattered or hard-coded.

Solution

A versioned REST API (/v1/companies) with server-side validation of every field, plus a Companies page with an inline-editable, paginated grid and a New Company form that surfaces server-side field errors.

User Personas and Stories
Who uses this feature and what they need to accomplish
Each story follows: As a [role], I want to [action] so that [benefit]. Acceptance criteria define when a story is done.
Administrator
As an administrator, I want to create a company so that its details and timezone are available to the rest of the system.
  • Given valid name, address, phone number and timezone, the company is created and appears in the list
  • Given an invalid timezone, the Timezone field shows the server's error and nothing is created
  • Given a name that already exists (any letter case), I see a conflict error
Administrator
As an administrator, I want to browse companies page by page so that the list stays fast as it grows.
  • The grid shows one page at a time with Previous, Next, page numbers and an "X of Y total" indicator
  • Changing the page size returns me to page 1
  • Previous and Next are disabled at the first and last page
Administrator
As an administrator, I want to edit a company inline so that corrections take seconds.
  • Double-clicking a row opens it for inline editing; Update saves it
  • A rejected change is reverted by reloading the page of data and the error is shown
  • Renaming a company to its own name in a different case is allowed
Administrator
As an administrator, I want to delete a company so that obsolete records disappear.
  • Selecting a row and choosing Delete removes it and shows a confirmation snackbar
  • Deleting the last row of a page beyond the first loads the previous page
Administrator
As an administrator, I want to open a single company by id so that other screens can link to it.
  • An unknown id returns a not-found error in the standard envelope

Risks and Assumptions
Known risks, open questions, and assumptions being made

Technical Risks

Data is lost on restart
Mitigation: the repository is in-memory by design. The ORM model documents the intended schema for a later database repository.
Browser timezone list differs from the server's list
Mitigation: the server is the authority and returns a field-level error for any name it does not know.
Grid add and edit bypass the form
Mitigation: both paths go through the same store action, Zod schemas and server validation.

Assumptions

#AssumptionIf Wrong, Impact
1Timezone is a single IANA name per companyMulti-site companies would need a separate location entity
2Phone numbers are international-style strings, not normalisedSearch and dedupe by phone would need normalisation
3Company names are unique ignoring caseLegitimate same-name companies would be blocked
